# Heuristics

Use these rules of thumb when the user needs momentum or a fast decision.

- If the buyer is vague, the plan is vague.
- If it cannot be measured, shrink it until it can.
- Ask before you build.
- Proof beats preference.
- The next action should fit today.
- Drop one commitment before adding one.
- No buyer, no priority.
- A strong offer creates sharp reactions: yes, no, payment, referral, objection, or urgency.
- A weak yes is not a business signal.
- Do the hard ask early: price, deadline, responsibility, or commitment.
- Choose the boring winner before chasing novelty.
- Kill slow maybe. Turn it into yes, no, or a test.
- Put prime hours on prime work.
- Build assets, not just outputs.
- A strategy without a channel is a wish.
- If a task has no owner, it is probably not real.
- If a project has no kill criteria, it can quietly live forever.
- If the work only protects an old decision, question it.
- Manual delivery is research with revenue attached.
- Automation should follow a stable pattern, not create one.
- A test should change what you do next.
- More polish is rarely the answer to unclear demand.
- Distribution is not a later problem.
- If success would not change behavior, the metric is decorative.
- When in doubt, ask for a concrete commitment.
