# Kill List — Template

Audit current commitments. Decide what to keep, change, or kill — in writing, today.

A maybe is a kill in disguise. Force a verdict.

## The Audit Table

| # | Commitment | Last touched | Named buyer | Owner | Current evidence rung | Path to revenue or learning | Action | Decision date |
| - | ---------- | ------------ | ----------- | ----- | --------------------- | --------------------------- | ------ | ------------- |
| 1 |            |              |             |       |                       |                             |        |               |
| 2 |            |              |             |       |                       |                             |        |               |
| 3 |            |              |             |       |                       |                             |        |               |

**Action options:** delete, delegate, shrink, pause, batch, convert-to-test.

## Drop-Candidate Triggers

Mark for kill consideration if any apply:

- [ ] No named buyer or beneficiary.
- [ ] No owner.
- [ ] No metric.
- [ ] No deadline.
- [ ] No path to revenue, retention, learning, or strategic leverage.
- [ ] No visible progress after repeated effort.
- [ ] Only sunk-cost justification.
- [ ] High energy drain relative to value.
- [ ] Last touched more than 30 days ago without a deliberate pause.

Three or more boxes checked → default verdict is kill, unless the user can name a specific buyer commitment due within 14 days.

## What Gets Captured Before Killing

For every kill, write the learning before deleting:

```text
Killed:              [commitment name]
Why it existed:      [original thesis]
Why it's dying:      [what proved the thesis wrong, or what proved capacity insufficient]
What we learned:     [pattern to remember next time]
What to reuse:       [content / contacts / drafts / code worth saving]
Capacity returned:   [hours/week, $/month, mental load]
```

The kill is not failure. Lost capacity returning to better work is the point.

## What Gets Captured Before Keeping

Anything not killed must justify staying alive:

```text
Kept:                [commitment name]
Named buyer:         [specific person or segment]
Scoreboard contribution: [which one number does this move]
Next proof test:     [what + by when + kill criterion]
Owner:               [name]
Time budget:         [hours/week]
Review date:         [next time this is re-audited]
```

If the user cannot fill in all six lines, the commitment moves to the kill list.

## Output

After the audit, write the summary:

```text
Audited:    [N items]
Kept:       [N — list]
Changed:    [N — list with the change]
Killed:     [N — list]
Capacity returned: [hours/week + $/month estimate]
Next audit: [date]
```
